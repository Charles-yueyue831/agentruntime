为什么 Instance 可以覆盖 Tool 的 MountPath，
却不等于绕过 Tool 的存储管控？

核心要区分：“挂到哪里” 和 “挂的到底是什么、最多能有什么权限”。

MountPath 是“位置”；StorageSource / ReadOnly 上限 / 路径规则，才决定“边界”。

① 先承认事实：Instance 的确可以覆盖 Tool 的 MountPath

Tool · StorageMount
Name = data CFS = cfs-123 Path = /datasets MountPath = /mnt/assets ReadOnly = false

/mnt/assets 是默认本地挂载位置。

→Instance 覆盖
Instance · MountOption
Name = data MountPath = /workspace/input SubPath = user-a ReadOnly = true

当前实例最终可以改成 /workspace/input。

② 但它到底“覆盖”了什么？

它改变的是

这份存储在沙箱文件系统里的“入口位置”

Tool 默认： CFS:/datasets → /mnt/assets Instance 覆盖后： CFS:/datasets/user-a → /workspace/input

也就是：Agent 在容器里要去哪个目录看到它。

它没有改变的是

“这份存储是谁”和“权限上限是什么”

仍然是：cfs-123 不能换成：cfs-456 不能新增：COS bucket-B 不能换成：image:v2

因为 MountOptions 只能引用 Tool 里已经存在的 StorageMount.Name。

③ Tool 和 Instance 的职责其实不是同一层

Tool：定义“允许使用什么” StorageSource + 默认 MountPath + ReadOnly 基线
↓
Instance：定义“这次怎么用” 引用 Name，覆盖 MountPath，追加 SubPath，收紧 ReadOnly
↓
最终挂载配置 源存储不变 + 实例级路径布局 + 最终权限
↓
真正执行 mount CFS:/datasets/user-a → Sandbox:/workspace/input

④ 真正的“管控边界”在哪里？

边界 1

存储来源

Tool 决定。

Instance 只能引用已存在的 StorageMount.Name，不能新增 StorageSource。

边界 2

权限上限

Tool 决定最大权限。

Instance 可以把可写收紧成只读，但不能把 Tool 级只读放宽成可写。

边界 3

路径合法性

平台统一校验。

即使覆盖 MountPath，也仍然要满足绝对路径、黑名单、重复路径等规则。

灵活层

容器内布局

Instance 可调整。

MountPath 主要解决“这份已经获准的存储在本实例里放哪里”。

⑤ 一张表看清“能改什么、不能改什么”

维度
Instance 能否改变？
含义
MountPath
✅ 能覆盖
改变容器内的挂载位置。
StorageSource
❌ 不能换
不能在启动实例时换成另一份 CFS / COS / Image。
新增存储来源
❌ 不能新增
MountOptions 只能引用 Tool 已存在的 StorageMount.Name。
ReadOnly 权限
⚠️ 只能收紧
true 可以覆盖 false；只读不能放宽为可写。
SubPath
✅ 可追加
在远端默认路径下追加实例级子目录，用于隔离。
路径合法性
❌ 不能绕过
最终 MountPath 仍要通过平台路径规则。

⑥ 所以“Tool 的 MountPath”到底是什么性质？

正确

默认布局

没有 Instance 覆盖时，实例继承它。

正确

复用模板

多数实例无需重复填写相同的本地挂载路径。

不要这样理解

不可变安全策略

因为 Instance 的 MountOptions.MountPath 本来就被设计成可覆盖。

⑦ 最关键的一张关系图

Tool 管： “你可以使用哪份存储？” “最多能不能写？” “默认挂到哪里？” │ ▼ Instance 管： “这次实例要从哪个 SubPath 用？” “这次实例想把它放到容器里的哪里？” “这次是否进一步收紧为只读？” │ ▼ 平台继续管： “最终路径是否合法？” │ ▼ 最终： 既保留 Tool 的资源边界， 又允许 Instance 做运行时布局。
一句话结论： Instance 覆盖 Tool 的 MountPath，只说明“本地路径布局可以运行时参数化”；它不代表 Instance 获得了替换存储来源、放宽权限或绕过路径校验的能力。

一分钟自测

Tool 定义：CFS=cfs-123、Path=/data、MountPath=/mnt/data、ReadOnly=true。Instance 能否把它改成 cfs-456 并设置 ReadOnly=false？

不能。它最多可以覆盖本地 MountPath、追加 SubPath，但不能替换 StorageSource，也不能把 Tool 级只读放宽成可写。
官方依据：
1. 腾讯云 Agent Runtime「存储挂载」：Tool 级 StorageMounts 定义默认存储来源、默认 MountPath 和默认 ReadOnly；Instance 级 MountOptions 可覆盖 MountPath、收紧只读权限、追加 SubPath，并且只能引用已存在的 StorageMount.Name。
2. 腾讯云 Agent Runtime「挂载文件系统 CFS」：明确说明实例默认继承 Tool 挂载配置，MountPath 可“覆写工具默认的本地挂载路径”，ReadOnly 只能收紧。
