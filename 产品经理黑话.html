WHY

01 · 为什么做

目的 / 目标 / 痛点 / 价值 / 意义 / 影响

目的

WHY · 根本意图
元定义

为什么要做这件事；它表达的是行动背后的根本意图，而不是量化终点。

腾讯云 Agent 沙箱例子

建设 Agent 沙箱的目的，是让 Agent 能在独立、受控的环境里执行代码、浏览器操作、文件处理等真实动作，而不是把不确定执行直接放在业务主机上。

目标

WHERE · 可验收终点
元定义

未来希望达到的明确状态；最好可量化、可验收、带时间边界。

腾讯云 Agent 沙箱例子

例如把“沙箱启动快”转化为目标：P95 启动时延低于某个业务阈值、任务结束后在规定时间内完成回收、创建成功率达到既定 SLO。

痛点

PROBLEM · 当前缺口
元定义

当前状态与期望状态之间，真正给用户造成成本、风险或阻塞的差距。

腾讯云 Agent 沙箱例子

例如：Agent 生成代码不宜直接在业务服务器执行；依赖环境复杂；多租户任务存在相互影响风险；任务结束后资源残留会造成浪费。

价值

BENEFIT · 对谁有收益
元定义

对象给特定主体带来的收益、改善或成本下降，必须回答“对谁、改善什么”。

腾讯云 Agent 沙箱例子

对开发者：减少自建执行环境的工程成本；对企业：获得更清晰的隔离、网络、生命周期和审计边界；对最终用户：缩短等待并降低任务互相干扰。

意义

SO WHAT · 为什么重要
元定义

某个事实或变化为什么重要，以及它进一步说明了什么更深层的趋势。

腾讯云 Agent 沙箱例子

Agent 沙箱把“执行代码”从业务中的零散函数提升为独立基础设施，说明 Agent 正从只生成文本，走向需要真实执行、安全边界与生产治理的阶段。

影响

AFTER · 后续改变
元定义

一个结果在后续时间里进一步改变了哪些对象、关系、决策或成本结构。

腾讯云 Agent 沙箱例子

引入沙箱后，Agent 架构会从“主进程直接操作业务环境”转向“通过独立执行层完成任务”；运维对象也增加 Tool、Instance、镜像、网络、存储、生命周期等。

THINK

02 · 怎么看问题

范式 / 格局 / 逻辑

范式

WORLDVIEW · 总框架
元定义

面对一类问题时，默认采用的基本假设、核心对象和总体解决框架；它决定“我们根本把问题看成什么”。

腾讯云 Agent 沙箱例子

传统方式是“先长期准备服务器，再把任务放进去”；Agent 沙箱范式是“先产生任务，再按任务创建独立、受控、可回收的执行环境”。腾讯云官方也将 Agent Runtime 描述为围绕 Agent 原生执行范式构建。

格局

LANDSCAPE · 谁在什么位置
元定义

一个市场或领域里主要参与者是谁、分别处于什么位置、彼此如何竞争或互补。

腾讯云 Agent 沙箱例子

分析 Agent 沙箱格局时，不只看功能清单，还会看云厂商、专业 Sandbox 厂商、Agent 框架、模型厂商、企业平台在资源、协议兼容、生态和客户层面的相对位置。

逻辑

WHY IT HOLDS · 因果关系
元定义

条件、原因、行为与结论之间为什么能够前后成立；它解释“为什么 A 可以推出 B”。

腾讯云 Agent 沙箱例子

Agent 行为存在不确定性 + 业务环境含重要数据 + 沙箱可以限制进程/网络/存储边界 ⇒ 错误操作的影响范围更容易被收缩 ⇒ 整体风险下降。

HOW

03 · 怎么解决

策略 / 方法 / 方式 / 打法 / 玩法 / 布局 / 发力 / 降维打法 / 落地

策略

CHOICE · 选择规则
元定义

为了达成目标，在资源与约束下如何选择、排序和取舍。

腾讯云 Agent 沙箱例子

网络策略示例：需要公网 API 时选 PUBLIC；只处理已挂载数据时选 SANDBOX；需要访问企业内部服务时选 VPC。策略的关键是“什么条件下选哪个”。

方法

METHOD · 系统化办法
元定义

为解决一类问题采用的、相对系统化且可重复的办法。

腾讯云 Agent 沙箱例子

为了实现沙箱数据持久化，可采用“把外部持久化存储挂载到沙箱”的方法；具体可使用 CFS/COS 等对应产品能力。

方式

MEANS · 具体怎么做
元定义

某一个具体动作采用什么实现手段、入口或渠道。

腾讯云 Agent 沙箱例子

同样是创建沙箱，可以通过 API、SDK、MCP 等方式触发；同样是查看状态，可以通过查询接口、CLI 或控制台观测。

打法

PLAYBOOK · 一整套行动
元定义

为打赢一个具体业务战役，把策略、方法、产品、资源、指标和节奏组合起来的一整套行动方案。

腾讯云 Agent 沙箱例子

例如 Coding Agent 打法：优先解决启动、协议兼容和状态恢复 → 找头部客户验证 → 形成模板与最佳实践 → 标准化后扩大覆盖。

玩法

PATTERN · 使用套路
元定义

产品或业务的一种可复用使用套路，通常比“打法”更局部、更贴近实际使用。

腾讯云 Agent 沙箱例子

玩法 A：每个任务一个临时沙箱；玩法 B：一个会话绑定一个沙箱；玩法 C：暂停/快照后下次恢复；玩法 D：提前预热环境再承接请求。

布局

POSITIONING · 提前占位
元定义

为了未来目标，提前在哪些方向配置产品、资源与位置。

腾讯云 Agent 沙箱例子

例如围绕 Agent Runtime 同时建设代码沙箱、浏览器沙箱、移动端沙箱、快照、持久化存储、网关、身份与观测，形成长期产品布局。

发力

FOCUS · 加大投入
元定义

当前把更多资源、注意力和组织动作集中投入到某个方向。

腾讯云 Agent 沙箱例子

“发力 Agent Sandbox”如果落到实处，通常意味着增加研发投入、完善协议兼容、提升关键性能、争取标杆客户并扩大市场曝光。

降维打法

ASYMMETRY · 不对称优势
元定义

把自己在更高资源、能力或成熟度维度上的优势带入一个相对能力较弱的竞争场景，形成不对称竞争。

腾讯云 Agent 沙箱例子

云厂商做 Agent Sandbox 时，可以把既有计算、VPC、CFS/COS、CAM、CLS、网关和企业服务体系组合进来，而不只竞争一个“沙箱 API”。

落地

SHIP · 从方案到真实使用
元定义

把概念、方案或技术真正转化为可用产品、真实业务和可验证结果。

腾讯云 Agent 沙箱例子

“Agent 应该安全执行代码”只有转化成 Tool/Instance、API、镜像、权限、网络、生命周期、日志、文档、SLO 与客户接入，才算完成产品落地。

PRODUCT

04 · 产品是什么

形式 / 模块 / 功能 / 能力 / 特点 / 特性

形式

FORM · 长什么样
元定义

对象以什么形态存在、被承载或呈现。

腾讯云 Agent 沙箱例子

Agent 沙箱可表现为 Sandbox Tool、Sandbox Instance、Sandbox Snapshot 等资源形态；也可表现为 code-interpreter、browser、mobile、osworld/custom 等运行环境形态，以及 API/SDK/CLI/MCP 等接入形态。

模块

STRUCTURE · 由什么组成
元定义

系统按职责边界拆成的组成部分，每部分负责相对独立的职责。

腾讯云 Agent 沙箱例子

可按产品分析拆为：Tool 配置、Instance 生命周期、计算调度、镜像、网络、存储、身份权限、代码/进程/文件操作、可观测、配额与快照恢复等模块。

功能

DO · 能做什么
元定义

产品或模块可以直接执行的操作，常可映射为 API、按钮或命令。

腾讯云 Agent 沙箱例子

例如创建 Tool、启动 Instance、执行 Shell、运行代码、上传/下载文件、查询实例、暂停/恢复/停止、配置网络与存储等。

能力

CAPABILITY · 稳定完成什么
元定义

综合多个功能、模块、资源与机制后，能够稳定完成的一类任务。

腾讯云 Agent 沙箱例子

“运行一段 Python”是功能；“在多租户环境下提供可治理的安全代码执行”则是由计算、镜像、隔离、网络、存储、生命周期和日志共同形成的能力。

特点

DIFFERENCE · 显著之处
元定义

与其他对象比较后显得突出的地方，带有“对比视角”。

腾讯云 Agent 沙箱例子

相对长期业务服务器，Agent 沙箱更强调按任务实例化、独立生命周期、强执行边界、快速启停以及为 Agent 工具调用而设计。

特性

PROPERTY · 自身属性
元定义

对象自身较稳定、可描述、可验证的属性，不要求与别人比较。

腾讯云 Agent 沙箱例子

例如独立生命周期、配置可继承、网络边界可选择、外部存储可挂载、可暂停/恢复、运行环境可模板化等。

RUN

05 · 系统怎么运行

机制 / 流程 / 状态 / 闭环 / 体系

机制

ENGINE · 内部怎么运转
元定义

内部各部分如何相互作用，从而产生某种行为或结果；机制解释“为什么系统能够工作”。

腾讯云 Agent 沙箱例子

启动实例时，控制面读取 Tool 配置 → 合并 Instance 本次配置 → 准备资源/镜像 → 配网络与存储 → 启动进程 → 健康检查 → Instance 进入可运行状态。

流程

FLOW · 先后顺序
元定义

一项任务从开始到结束，角色、步骤和状态按照什么顺序衔接。

腾讯云 Agent 沙箱例子

用户任务 → Agent 判断需要执行 → 创建 Instance → 启动 → 上传/读取文件 → 执行代码 → 获取结果 → 保存产物 → 停止/回收。

状态

STATE · 现在在哪
元定义

对象在某一个时间点现在处于什么情况或生命周期阶段。

腾讯云 Agent 沙箱例子

例如 Tool 正在创建/可用/失败；Instance 在启动、运行、暂停、恢复、停止等阶段。状态回答“现在在哪”，不是“做得好不好”。

闭环

LOOP · 反馈再行动
元定义

结果能被观测并反馈回来，驱动下一轮判断与动作，形成“输入—执行—反馈—调整”的循环。

腾讯云 Agent 沙箱例子

启动慢 → 采集启动数据 → 定位镜像准备耗时 → 做镜像预热/缓存 → 再测试 → 指标达标则推广，否则继续调整，这才是性能优化闭环。

体系

SYSTEM · 系统化整体
元定义

多个相互关联的模块、机制、规则、流程组成的系统化整体。

腾讯云 Agent 沙箱例子

“生命周期体系”不是只有 Stop API，而是创建、状态机、超时、暂停/恢复、停止、自动回收、快照、错误处理、观测和运营规则的整体。

MEASURE

06 · 怎么判断好不好

性能 / 数据 / 测试 / 评估 / 阈值 / 高优 / 体验 / 结果 / 效果 / 作用

性能

PERF · 快/大/稳/耗
元定义

在特定条件下，完成任务有多快、多大、多稳，以及消耗多少资源。

腾讯云 Agent 沙箱例子

常见指标包括启动时延、并发实例数、创建吞吐、成功率、CPU/内存、磁盘 I/O、网络吞吐、P95/P99、任务执行耗时和资源成本。

数据

FACT · 可记录事实
元定义

对事实、行为和结果进行记录或量化后的信息。

腾讯云 Agent 沙箱例子

例如 InstanceId、ToolId、Status、CreateTime、启动耗时、CPU、内存峰值、错误码、网络流量、任务完成率和日志事件。

测试

TEST · 人为验证
元定义

人为设置条件，通过实验验证系统行为是否符合预期。

腾讯云 Agent 沙箱例子

例如固定地域、镜像和资源规格，连续创建 10,000 个 Instance，观察 P50/P95/P99、失败率、超时率和资源峰值。

评估

JUDGE · 对照标准
元定义

依据数据、指标、基线与标准，对对象作出判断。

腾讯云 Agent 沙箱例子

如果目标是 P99 < 2 秒、失败率 < 0.5%，测试得到 P99=1.7 秒、失败率=0.3%，则可以形成“达标”的评估结论。

阈值

TRIGGER · 临界线
元定义

触发某种判断或动作的临界值。

腾讯云 Agent 沙箱例子

例如 CPU > 80% 触发告警；创建失败率 > 1% 停止灰度；实例空闲超过既定时间触发回收。

高优

PRIORITY · 先处理什么
元定义

相对于其他待办，需要更早投入资源处理的事项；本质是优先级排序。

腾讯云 Agent 沙箱例子

例如大规模创建失败通常高于“控制台字段说明不够清晰”；高优不只是“很严重”，还意味着在当前资源约束下应先处理。

体验

UX · 用户感受
元定义

用户完成整个任务过程中，对效率、理解成本、稳定性与操作连贯性的综合感受。

腾讯云 Agent 沙箱例子

两个平台都能创建沙箱，但一个需要 20 个必填字段且失败只报 InternalError，另一个模板预设、状态清晰、错误原因明确；功能相似，体验可能差很多。

结果

OUTPUT · 客观产物
元定义

行为或流程结束后，客观产生了什么事实、产物或状态。

腾讯云 Agent 沙箱例子

例如成功创建 Instance、生成 report.csv、返回执行结果、写入持久化存储、最终进入 STOPPED，或者失败并产生明确错误原因。

效果

EFFECT · 相对目标如何
元定义

实际结果相对于目标、预期或基准表现如何。

腾讯云 Agent 沙箱例子

“Instance 创建成功”是结果；“P95 从 10 秒降到 1 秒并达到既定目标”才是效果。效果必须有参照物。

作用

ROLE · 场景里起什么用
元定义

对象放进一个具体场景后起什么用、解决什么问题。

腾讯云 Agent 沙箱例子

沙箱的作用是把 Agent 的不确定执行放进受控边界；快照的作用是减少重复初始化；VPC 网络的作用是让沙箱访问企业内部服务。

IMPROVE

07 · 怎么持续变好

反馈 / 跟进 / 优化 / 迭代 / 敏捷 / 回顾 / 沉淀 / 创新

反馈

FEEDBACK · 返回信息
元定义

执行后的信息返回给决策者，为下一轮判断提供输入。

腾讯云 Agent 沙箱例子

例如客户反馈某网络模式下无法满足日志投递诉求，或者任务创建偶发超时；这些信息进入产品、研发和运维决策。

跟进

FOLLOW-UP · 持续推进
元定义

对尚未结束的问题持续推动，直到得到下一状态或最终关闭。

腾讯云 Agent 沙箱例子

客户反馈挂载失败 → 建单 → 定位 → 修复 → 发布 → 通知客户 → 客户验证，这是一条完整跟进链。

优化

TUNE · 改善指标
元定义

在已有方案上改善某项或多项指标，通常不改变产品本质。

腾讯云 Agent 沙箱例子

例如调整镜像缓存和资源准备，使启动时间下降；优化参数校验，使错误更早暴露、更容易理解。

迭代

ITERATE · 一版接一版
元定义

基于上一版本形成下一版本，把新能力、修复和学习持续加入产品。

腾讯云 Agent 沙箱例子

V1 只有启动/停止 → V2 增加暂停恢复 → V3 增加快照 → V4 增加更完整的状态治理，这就是产品迭代。

敏捷

AGILE · 小步快跑
元定义

用小步交付、快速反馈和频繁调整降低大规模一次性交付的不确定性。

腾讯云 Agent 沙箱例子

不一次性做完“完整沙箱治理平台”，而是先补状态、再补错误原因、再补告警、再补运营分析，每一步都基于真实反馈调整。

回顾

REVIEW · 回头看
元定义

事情结束后重新分析发生了什么、为什么发生、哪些措施有效、下次如何改变。

腾讯云 Agent 沙箱例子

一次高峰创建失败后，按时间线、指标、根因、应急处置、长期修复和遗漏项进行复盘。

沉淀

ASSET · 经验变资产
元定义

把一次性经验转化为能够长期复用的知识、规则、工具或产品能力。

腾讯云 Agent 沙箱例子

一次 CFS 路径问题处理后，把经验变成字段语义规范、控制台校验、FAQ、自动诊断和测试用例，才算真正沉淀。

创新

INNOVATE · 新办法带来新价值
元定义

采用新的问题解决方式并产生新的有效价值，而不只是“以前没做过”。

腾讯云 Agent 沙箱例子

例如把运行时快照、预热和任务级环境结合起来，显著改变长会话 Agent 的启动与资源模型，才更接近产品创新。

GROWTH

08 · 怎么增长

流量 / 导流 / 分发 / 转化 / 裂变 / 渠道下沉 / UGC

流量

TRAFFIC · 进入规模
元定义

进入某个入口的人、请求或注意力规模。

腾讯云 Agent 沙箱例子

可对应 Agent Runtime 文档访问量、控制台访问、SDK 下载、API 调用、试用申请等不同层面的“流量”。

导流

ROUTE · 把人引过去
元定义

把已有流量引向另一个目标入口。

腾讯云 Agent 沙箱例子

例如在 Coding Agent 教程中引导用户进入 Agent Sandbox 快速入门，并继续创建第一个 Tool/Instance。

分发

DISTRIBUTE · 送达用户
元定义

把产品、内容或能力主动送到目标用户面前。

腾讯云 Agent 沙箱例子

可以通过官网、开发者文档、SDK、Agent Framework 集成、云市场、教程与生态合作把 Agent Sandbox 能力分发出去。

转化

CONVERT · 进入下一阶段
元定义

用户从一个业务阶段成功进入下一个关键阶段。

腾讯云 Agent 沙箱例子

例如：访问文档 → 进入控制台 → 创建 Tool → 首次启动 Instance → 持续使用；每一步都可以计算转化率。

裂变

VIRAL · 用户带用户
元定义

已有用户进一步带来新用户或新传播，使增长形成传播链。

腾讯云 Agent 沙箱例子

假设未来开发者能分享可复用的 Sandbox 模板/镜像/工作流，A 分享给 B/C，B 再传播给团队，就形成裂变。

渠道下沉

EXPAND · 覆盖更广
元定义

从原有核心客户与核心渠道，继续进入更广、更基层或更细分的市场。

腾讯云 Agent 沙箱例子

例如先服务大型模型厂商与头部 Agent 公司，再逐步覆盖中型 SaaS、小团队和独立开发者。

UGC

CONTENT · 用户生产
元定义

User Generated Content：由用户而不是平台官方创造的内容。

腾讯云 Agent 沙箱例子

若开发者可以创建并分享 Sandbox 模板、镜像、Tool 配置、Skill 或工作流，这些用户贡献物就是 UGC；此处用于解释概念，不表示当前一定存在完整公开 UGC 市场。

MARKET

09 · 怎么经营市场

头部 / 腰部 / 长尾 / 垂直 / 生态 / 商业模式 / 沉浸

头部

TOP · 少而大
元定义

数量较少，但规模、影响力、收入或行业示范效应很大的参与者。

腾讯云 Agent 沙箱例子

例如日调用量极高的大模型厂商、头部 Coding Agent 平台或超大型企业客户，通常会被放在“头部客户”分析中。

腰部

MID · 中等规模
元定义

介于头部与大量长尾之间的中等规模参与者，通常需求稳定且有成长空间。

腾讯云 Agent 沙箱例子

中型 Agent 创业公司、成熟 SaaS 团队可能属于腰部客户；它们常适合标准化方案复制。

长尾

TAIL · 多而小
元定义

单体规模较小，但数量巨大的用户、需求或场景集合。

腾讯云 Agent 沙箱例子

独立开发者、小团队、低频但类型众多的 Agent 场景，单个规模不大，合在一起形成长尾。

垂直

VERTICAL · 深耕一个场景
元定义

集中解决一个具体行业、场景或用户群的问题，而不是横向覆盖所有市场。

腾讯云 Agent 沙箱例子

可以把 Agent Sandbox 进一步按 Coding Agent、Browser Agent、RL、办公 Agent 等垂直场景研究。

生态

ECOSYSTEM · 多方价值网络
元定义

多类参与者相互依赖、相互连接并共同创造价值形成的网络。

腾讯云 Agent 沙箱例子

云平台、Agent 框架、模型厂商、Sandbox 协议、镜像/Skill 开发者、Agent 应用与企业客户共同构成 Agent Runtime 生态。

商业模式（“一砣商业模式”）

BUSINESS · 如何赚钱并持续
元定义

企业如何创造价值、交付价值并从中获取收益；“一砣商业模式”是非正式调侃表达，正式文档建议使用“商业模式”。

腾讯云 Agent 沙箱例子

分析 Agent Sandbox 商业模式要同时看客户是谁、价值主张、交付渠道、资源成本、计费单位、毛利结构、规模效应和生态关系，而不只是“怎么收费”。

沉浸

IMMERSION · 连续任务体验
元定义

用户持续处在连贯任务环境中，很少因工具切换或上下文中断而退出任务状态。

腾讯云 Agent 沙箱例子

在一个 All-In-One 或连续会话型环境里，Agent 可连续运行代码、操作浏览器、读取文件、打开终端并继续执行，体验上更“沉浸”。

RESOURCE

10 · 怎么组织资源

撬动 / 盘活 / 整合 / 操盘 / 干货

撬动

LEVERAGE · 小投入带大资源
元定义

用较少新增投入激活更多已有资源，从而产生更大的结果。

腾讯云 Agent 沙箱例子

一个 Agent Sandbox 产品可以撬动既有计算、VPC、CFS/COS、CAM、日志与网关能力，组合成更完整的 Agent 执行平台。

盘活

ACTIVATE · 存量再利用
元定义

使原本已经存在但利用不足的存量资源重新产生价值。

腾讯云 Agent 沙箱例子

如果通过弹性调度把部分闲置算力用于短时 Agent Sandbox 任务，可以理解为“盘活存量算力”的一种方式。

整合

INTEGRATE · 分散变统一
元定义

把原本分散的能力、资源或团队组合成一个统一解决方案。

腾讯云 Agent 沙箱例子

计算 + 网络 + 存储 + 身份 + 日志 + Sandbox 通过统一产品体验被组织起来，就是能力整合。

操盘

OPERATE · 全局经营
元定义

围绕整体业务目标，持续协调产品、资源、团队、客户、市场和节奏。

腾讯云 Agent 沙箱例子

操盘 Agent Sandbox 不只是写 PRD，而是定位场景 → 排路线 → 协调研发 → 找标杆客户 → 灰度 → 看数据 → 调产品/价格 → 扩规模。

干货

SIGNAL · 高信息密度
元定义

能够直接帮助理解、决策或操作的高信息密度内容，是互联网语境中的非正式说法。

腾讯云 Agent 沙箱例子

“Agent Sandbox 很强”不是干货；把 PUBLIC/VPC/SANDBOX 的差异、限制、选择条件和错误案例讲清楚，才更接近干货。

AUDIT

11 · 怎么证明可信

审计

审计

TRUST · 证据链
元定义

依据标准与证据检查过程和结果是否真实、完整、合规、可靠，并形成可追溯判断。

腾讯云 Agent 沙箱例子

可以用调用身份、RequestId、ToolId、InstanceId、镜像/配置、网络策略、状态、时间戳、日志和产物等证据，检查一次 Agent 执行是否按授权发生、是否越权、结果是否可追踪。

最终总链路：一个产品问题是怎么从“想法”走到“价值”的？

痛点→目的→目标→范式→逻辑→策略→方法→方式→模块/功能→机制/流程→状态/数据→结果→效果→作用→价值→影响→意义

腾讯云 Agent 沙箱的一句话范式

不要把 Agent 的不确定执行直接放在长期业务主机里；把每个任务看成“需要独立执行环境的任务”，再通过 Tool 模板化、Instance 实例化、网络/存储/权限策略和生命周期治理来承载。

产品经理使用这套词典的方法

写 PRD、竞品分析或问题复盘时，先标注句子属于“目的 / 目标 / 策略 / 机制 / 结果 / 效果 / 价值”中的哪一层。只要层级错了，讨论很容易把功能当能力、把结果当效果、把打法当范式。
